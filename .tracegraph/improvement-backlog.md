## Observability research batch (2026-05-17)

- [x] **Per-step token usage in traces** (LangSmith state snapshots) — ensure `TraceStep` carries `Usage(promptTokens, completionTokens)` populated from `NodeListener.onUsage`; verify `JsonFileTraceStore` and `JdbcTraceStore` persist it; add query helper `ExecutionTrace.totalUsage()`. Tests via `MockLlmClient` + `InMemoryTraceStore`. Weakness: token costs are tracked at listener level only, not queryable per execution step.
- [x] **Configurable sensitive-data logging flag** (Semantic Kernel diagnostic env vars) — add `Graph.Builder.sensitiveDataLogging(boolean)` (default `false`); when `true`, store full LLM prompt/response text in `TraceStep.rawInput` / `TraceStep.rawOutput`; when `false`, store only metadata (model name, token counts, finish reason). Propagate via `Context`. Tests with both flags. Weakness: no way to audit what data is stored in traces without code inspection.
- [x] **Micrometer metrics bridge** (Spring AI `ChatClient` / LangChain4j Micrometer) — new `MicrometerNodeListener` in `tracegraph-observability` emitting `tracegraph.node.duration` timer, `tracegraph.node.errors` counter, `tracegraph.llm.tokens` counters to a `MeterRegistry`; wire via `Graph.Builder.listener(...)`. Tests with `SimpleMeterRegistry`. Weakness: no JVM throughput/latency metrics exported to Prometheus/Grafana-compatible systems.
- [x] **Trace sampling wrapper** (Mastra sampling strategies) — `SamplingTraceStore(delegate, SampleStrategy)` in `tracegraph-observability` where `SampleStrategy` is a `@FunctionalInterface` receiving `ExecutionTrace<S>` and returning `boolean`; built-in strategies: `random(rate)`, `slowExecutions(thresholdMs)`, `failedOnly()`. Wire via `.traceRecorder(new RecordingTraceRecorder(new SamplingTraceStore(...)))`. Tests with deterministic strategies. Weakness: no way to control data volume for high-throughput graphs.
- [x] **Multi-agent interaction correlation** (AutoGen message span tracking) — extend `ExecutionTrace` with optional `parentExecutionId` and `parentStepIndex` for subgraph / `sendAll` causality (mirrors `forkedFromExecutionId` pattern); populate in `RecordingTraceRecorder` when `Graph.runFrom` is called from a subgraph context. Update `JsonFileTraceStore` schema. Tests with a parent graph embedding a subgraph. Weakness: child execution traces are isolated; no link back to the parent step that spawned them.
- [x] **Cost breakdown by node and provider** (Langfuse cost analytics) — extend `LlmCostListener` to expose `Map<String, Usage> usageByNode()` and `Usage totalUsage()` on a per-execution basis; add `LlmCostListener.snapshot(executionId)` returning an immutable `CostReport`. Tests with multi-node multi-LLM graph using `MockLlmClient`. Weakness: `LlmCostListener` accumulates global totals; no per-node or per-execution breakdown for billing.
- [x] **OTel semantic conventions for LLM spans** (Semantic Kernel / OpenTelemetry GenAI SIG) — update `OtelNodeListener` to emit the [GenAI semantic convention](https://opentelemetry.io/docs/specs/semconv/gen-ai/) attributes (`gen_ai.system`, `gen_ai.request.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, `gen_ai.response.finish_reasons`) on spans for `ChatNode` executions. Tests via span attribute assertions. Weakness: current OTel spans use ad-hoc attribute names incompatible with standard APM dashboards.
- [x] **Trace correlation ID for external system linkage** (LangGraph + Langfuse `trace_id`) — add `Graph.Builder.correlationId(Supplier<String>)` (or derive from incoming HTTP header); store in `ExecutionTrace.correlationId`; `OtlpTraceExporter` emits it as a span link attribute. `TraceController` returns it in `GET /tracegraph/traces/{id}`. Tests with a static supplier. Weakness: no way to correlate a TraceGraph execution with an upstream request trace in external APM.
- [x] **Slow-node alert listener** (CrewAI task-level SLA) — `SlowNodeListener(Map<String, Duration> budgets, Consumer<SlowNodeEvent> handler)` in `tracegraph-observability`; fires `handler` when a node exceeds its named budget (or a default); does NOT throw, just notifies. Tests with a node that sleeps past its budget. Weakness: no built-in SLA enforcement or alerting when a node takes unexpectedly long.
- [x] **Structured trace export to JSONL** (Haystack pipeline tracing export) — `JsonlTraceExporter.export(TraceStore, Path)` in `tracegraph-observability` writes one JSON object per `TraceStep` to a JSONL file suitable for ingestion by LangSmith, Langfuse, or Arize via their batch import APIs. Weakness: no bulk export format; traces can only be read through the REST API or `TraceStore.load(id)`.

## Eval-harness research batch (2026-05-17)

- [x] **BLEU / ROUGE / F1 text metrics** (DeepEval, Ragas parity) — add `BleuMetric<S>`, `RougeMetric<S>`, `TokenF1Metric<S>` under `tracegraph-eval/src/main/java/io/tracegraph/eval/metric/` implementing the existing `Metric<S>` SAM; tokenization is whitespace-only (no new deps) and `passThreshold` is a constructor arg returning a `MetricScore` via the standard `pass`/`fail` factories. Tests parallel `ExactMatchMetricTest`. Weakness: only exact/contains/embedding-similarity string metrics exist today, so partial-overlap quality (typical NLG output) is unscoreable.
- [x] **Threshold-gated suite pass/fail** (promptfoo, OpenAI Evals CI gates parity) — extend `EvalSuite.Builder<S>` with `failFast(boolean)` and `minPassRate(double)`, plus an `EvalSuite.assertPassed(List<EvalResult<S>>)` helper that throws `EvalAssertionException` so CI jobs invoking `mvn test` fail on regression; `EvalReport.toJUnitXml` already encodes per-case failures so the JUnit gate is end-to-end. Weakness: `EvalSuite.run()` returns results but never fails the build — there is no programmatic "did the suite pass" check today.
- [x] **Baseline snapshot + comparison** (LangSmith experiment tracking parity) — add `EvalBaseline` record (list of `MetricScore` keyed by `EvalCase.id()`) plus `EvalBaselineStore` (JSON file under `tracegraph-eval/src/main/java/io/tracegraph/eval/baseline/`) and `EvalReport.toComparisonMarkdown(current, baseline)` rendering per-case score deltas (regression/improvement arrows). Reuses the existing `EvalResult<S>` shape so no metric API change. Weakness: every `EvalSuite` run is standalone — there is no way to detect that today's run scored lower than yesterday's on the same case.
- [x] **CSV / JSONL dataset loaders** (OpenAI Evals JSONL registry, promptfoo CSV parity) — `EvalCaseLoader.fromJsonl(Path, Function<JsonNode, S>)` and `EvalCaseLoader.fromCsv(Path, Function<Map<String,String>, S>)` under `tracegraph-eval/src/main/java/io/tracegraph/eval/dataset/` producing `List<EvalCase<S>>` for `EvalSuite.Builder.addCases`. JSONL path uses the existing Jackson `<optional>` dep already pulled by `JsonFileTraceStore`; CSV path is hand-rolled (no new deps). Weakness: every `EvalCase<S>` must be constructed in Java code today — there is no way to keep an eval dataset in version-controllable data files.
- [x] **Parallel suite execution on virtual threads** (Inspect AI, Mastra parallel runners parity) — add `EvalSuite.runParallel(Executor)` alongside the existing `run()` that fans each `runCase` onto the supplied executor (default `Executors.newVirtualThreadPerTaskExecutor()`, lazily created and shut down like `Graph.run`'s default executor) and joins results in declaration order. `Metric.score` is already pure-of-input so no sync needed. Weakness: sequential `run()` is the only option, so 100-case suites against real `LlmClient` judges block end-to-end on network latency.
- [x] **Suite summary stats + latency percentiles** (Ragas aggregates, TruLens dashboards parity) — `EvalReport.toSummaryMarkdown(List<EvalResult<S>>)` rendering pass rate, per-metric mean score, and latency p50/p95/p99 (computed in-place over `EvalResult.latencyMs`) at the top of the existing Markdown table; expose the computed values as an `EvalSummary` record so callers can assert on them. Weakness: the current `EvalReport.toMarkdown` is per-case rows only — there is no aggregate signal for "is the suite healthier than last week".
- [x] **Conditional metric skipping** (DeepEval `evaluation_params` parity) — add a default `boolean canScore(EvalCase<S> evalCase)` method to `Metric<S>` returning `true`; `EvalSuite.runCase` consults it and emits a `MetricScore` with `passed=true, score=Double.NaN, detail="skipped"` for metrics that can't grade a given case (e.g., `LlmJudgeMetric` when `evalCase.expected()` is null). `EvalReport` renders "—" for NaN scores. Weakness: today every metric runs on every case, so a suite mixing classification cases (with `expected`) and open-ended cases (without) double-fails on the open ones.
- [x] **Per-step trace assertions on golden traces** (TruLens Selector API, agentic evaluators parity) — add `TraceAssertion<S>` SAM (`Optional<String> check(TraceStep<S> step)`) and `EvalRunner.Builder.assertion(String nodeName, TraceAssertion<S>)` that runs against each matching step of the captured `ExecutionTrace<S>` after a golden run; failures populate a new `GoldenEvalResult.assertionFailures` list and flip `passed` to false. Leverages the existing `runStore`-backed trace capture path in `EvalRunner.evaluateWithTrace`. Weakness: `GoldenEvalResult` only grades on final-state + status equality — intermediate node behaviour (tool args, retrieved docs, retry counts) is invisible to the eval, defeating TraceGraph's "deep observability" advantage.

## Multi-agent-patterns research batch (2026-05-18)

- [x] **Peer-to-peer handoff node** (CrewAI delegation, OpenAI Swarm) — add `HandoffNode<S>` in `tracegraph-connectors/llm` producing a `RoutingNode<S>` that, after an LLM call, reads a target-agent name from state via a `Function<S, String> handoffSelector` and emits `NodeResult.goTo(target, state)` directly to another named ReAct agent subgraph in the same `Graph<S>`, with no supervisor in the loop; reserved name `"continue"` falls through to the next declared agent and `null`/unknown target terminates at `"done"`. Public API: `HandoffNode.<S>builder().client(...).requestFactory(...).responseFolder(...).handoffSelector(...).target("name", graph)...build().buildGraph()`. Test: two agents `alice`/`bob` with a `MockLlmClient` script (`alice → bob → done`) asserting trace step order. Weakness: today every multi-agent flow must route through `SupervisorAgent`; there is no graph primitive for an agent to hand control directly to another agent.
- [ ] **Per-agent role + tool isolation** (CrewAI `Role`, LangChain4j per-agent `ToolProvider`) — add `AgentProfile<S>` record (`name`, `systemPrompt`, `List<Tool>`, `List<ToolDefinition>`, optional `Function<S, S> memoryScope`) in `tracegraph-connectors/llm` plus `ReActAgent.Builder<S>.profile(AgentProfile<S>)` that overrides the agent's tools and prepends the role prompt into every `LlmRequest` produced by `requestFactory`; calling `profile(...)` replaces any prior `tool(...)` registrations to enforce isolation. Test: two `ReActAgent<S>`s built from different `AgentProfile`s under the same `LlmClient` cannot see each other's tools (assert via `MockLlmClient` that records the requested tool list per call). Weakness: today `ReActAgent.Builder` accumulates `Tool` and `ToolDefinition` lists globally and has no notion of an agent identity or role, so swarms share a single tool pool.
- [x] **Group-chat agent pattern** (AG2 `GroupChat`, AutoGen) — add `GroupChatAgent<S>` factory in `tracegraph-connectors/llm` producing a `Graph<S>` where N named `ReActAgent`s rotate via either round-robin (`SpeakerSelector.roundRobin()`) or LLM-selected (`SpeakerSelector.llm(LlmClient, Function<S, LlmRequest.Builder>, Function<S, String>)`) speaker order; a `Predicate<S> terminationPredicate` halts the loop and routes to `"done"`. Public types: `GroupChatAgent<S>`, `SpeakerSelector<S>` (`@FunctionalInterface`: `String next(S state, List<String> agentNames)`). Test: three `MockLlmClient`-backed agents under round-robin produce a deterministic trace of speakers `a → b → c → a → done` when the predicate fires on round 4. Weakness: `SupervisorAgent` only supports star-topology routing through a single router; there is no built-in pattern for peer-to-peer rotation or LLM-selected turn order.
- [ ] **Voting / consensus aggregator node** (Semantic Kernel voting, AG2 reflection) — add `VotingNode<S>` in `tracegraph-connectors/llm` that fans `parallel(...)` across N named candidate `ReActAgent` subgraphs, then aggregates each candidate's contribution via a `BiFunction<S, List<S>, S> tallyFn` to produce the winning state; ships built-in tallies `Tally.majority(Function<S, String>)` and `Tally.firstNonNull(Function<S, String>)`. Public API: `VotingNode.<S>builder().candidate("alice", aliceGraph).candidate("bob", bobGraph).tally(Tally.majority(State::answer)).build()` returning a `Node<S>` insertable via `Builder.node(...)`. Test: three agents returning `"red"`, `"red"`, `"blue"` under `Tally.majority` produce a state whose answer is `"red"`. Weakness: `parallel(...)` plus a hand-written `Merger<S>` is the only way to express consensus today; quorum and majority voting are reimplemented per project.
- [ ] **Termination-predicate listener** (AG2 `max_turns`, BAML `max_iterations`) — add `TerminationListener<S>` in `tracegraph-observability` implementing `NodeListener` that, on each `onExit`, evaluates a user-supplied `Predicate<TerminationContext<S>>` (record: `nodeName`, `nodesEnteredSoFar`, `afterState`) and, when true, throws `TerminationSignalException` which the executor surfaces as a clean `Status.TERMINATED` (new enum constant) rather than a failure. Built-in predicates: `TerminationListener.maxTurns(int)`, `TerminationListener.afterNode(String)`, `TerminationListener.stateMatches(Predicate<S>)`. Test: an infinite supervisor loop halts cleanly after 5 router-agent rounds via `maxTurns(10)`. Weakness: termination is ad-hoc — every multi-agent factory reimplements its own `maxRounds` / `maxIterations` counter on top of `Graph.maxSteps`, with no shared, listener-shaped convergence contract.
- [ ] **Per-agent memory scoping** (CrewAI per-role memory, LangGraph `namespace`) — add `ScopedMemoryStore` decorator in `tracegraph-memory` that wraps an existing `MemoryStore` and prefixes every `scope` argument with a fixed `agentId` (e.g., `"alice/conversation"` instead of `"conversation"`), plus `MemoryStore.scopedTo(String agentId)` as a `default` method on the core SPI returning a `MemoryStore` view; uses the `default` so existing impls (`InMemoryMemoryStore`, `FileMemoryStore`, `JdbcMemoryStore`) inherit it for free. Test: two agents sharing one `InMemoryMemoryStore` but with different `scopedTo("alice")` / `scopedTo("bob")` views cannot read each other's keys. Weakness: `MemoryStore` is one global namespace and agents must self-prefix scope strings — partition is by convention, not by contract.
- [ ] **Reflexion / self-critique loop builder** (Reflexion paper, LangGraph `reflexion` recipe) — add `ReflexionAgent<S>` factory in `tracegraph-connectors/llm` producing a `Graph<S>` with three named nodes — `act`, `critique`, `revise` — wired `act → critique → (pass? done : revise → act)` where `critique` calls a critic `LlmClient` whose response is folded via `BiFunction<S, LlmResponse, S> critiqueFolder`, and a `Predicate<S> acceptPredicate` decides termination; `maxRevisions` caps the loop. Public API: `ReflexionAgent.<S>builder().actor(LlmClient).critic(LlmClient).requestFactory(...).critiqueFactory(...).acceptPredicate(...).maxRevisions(3).build().buildGraph()`. Test: a `MockLlmClient` that scripts `"draft → critique:bad → revise → critique:ok"` produces a 4-step trace ending at `done`. Weakness: `RetryPolicy` recomputes identical input; there is no built-in reflect-and-improve loop where output of one call becomes critic input for the next.
- [ ] **Plan-and-execute factory** (LangGraph plan-and-execute, BabyAGI) — add `PlanExecuteAgent<S>` in `tracegraph-connectors/llm` producing a `Graph<S>` with nodes `plan` (one LLM call producing an ordered task list folded into state via `BiFunction<S, LlmResponse, S> planFolder`), `step` (a `RoutingNode<S>` that pops the next task and dispatches via `NodeResult.goTo` to a named executor `ReActAgent` subgraph), and `done` (terminal when the task list is empty). Public API: `PlanExecuteAgent.<S>builder().planner(LlmClient).executor("research", researchAgent).executor("write", writeAgent).requestFactory(...).planFolder(...).taskSelector(Function<S, String>).remainingTasks(Function<S, List<?>>).build().buildGraph()`. Test: a planner that emits two tasks `[research, write]` produces a trace of `plan → step → research → step → write → step → done`. Weakness: planner-executor decomposition exists in TraceGraph only as hand-coded `RoutingNode` + `subgraph` wiring; there is no first-class builder.
- [ ] **Agent registry with dynamic lookup** (CrewAI `crew.agents`, AG2 `Agent` registry) — add `AgentRegistry<S>` SPI in `tracegraph-core/spi` and `InMemoryAgentRegistry<S>` impl in `tracegraph-connectors` keyed by agent id, returning compiled `Graph<S>` handles with `register(String id, Graph<S> graph, Map<String, String> tags)`, `lookup(String id)`, and `findByTag(String tag) → List<String>`; `Context.agentRegistry()` exposes the bound registry to nodes via a new `Graph.Builder.agentRegistry(AgentRegistry<S>)` setter (default no-op on `Context` so existing impls aren't broken). Public types: `AgentRegistry<S>`, `AgentRegistry.Entry<S>(String id, Graph<S> graph, Map<String, String> tags)`. Test: register two agents tagged `"research"`/`"writing"`, look up by tag from inside a `RoutingNode<S>`, dispatch to the resolved agent via `NodeResult.goTo`. Weakness: agents are wired at `Graph.Builder` time and there is no runtime lookup, so swarms cannot grow or shrink without a graph rebuild.
