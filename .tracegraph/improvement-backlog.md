research-angle: observability

## Active backlog

- [x] **Human-in-the-loop state-edit endpoint** (LangGraph Studio parity) — extend `TraceReplayController` with `POST /tracegraph/traces/{id}/resume` body to override state at an `interruptPending` checkpoint before resuming. Address weakness: HITL today is resume-only, no state mutation.
- [x] **Time-travel fork endpoint** (LangGraph time-travel) — `POST /tracegraph/traces/{id}/fork?step=N` returning new executionId; wraps existing `ReplayRunner.reRunFrom`. Weakness: replay is library-only, no REST surface.
- [x] **Structured output node** (Spring AI `BeanOutputConverter`, BAML) — `StructuredOutputNode<S, T>` in `tracegraph-connectors` that wraps an `LlmClient`, injects a JSON schema into the prompt, parses + validates response into `T` via Jackson, retries on parse failure (configurable, default 1). Tests with `MockLlmClient`.
- [x] **Vector-store SPI** (LangChain4j `EmbeddingStore`, Spring AI `VectorStore`) — `VectorStore` SPI in `tracegraph-core/spi` (`add`, `similaritySearch(queryEmbedding, k)`), `InMemoryVectorStore` (cosine, brute-force) in `tracegraph-connectors`. Wire via `Graph.Builder.vectorStore(...)` exposed on `Context`.
- [x] **Embeddings client SPI** (parallel to `LlmClient`) — `EmbeddingClient.embed(List<String>) → List<float[]>` in `tracegraph-connectors`, `MockEmbeddingClient` for tests, `OpenAiEmbeddingClient` adapter using the existing `HttpClient` pattern.
- [x] **Streaming tool-call deltas** (OpenAI/Anthropic streaming tool use) — extend `LlmStreamChunk` with optional `toolCallDelta(index, nameDelta, argsDelta)`; update `OpenAiLlmClient.stream` to surface them. Weakness: streaming is text-only today.
- [x] **Token-budget guard listener** (Langfuse cost guards) — `TokenBudgetListener(maxPromptTokens, maxCompletionTokens)` in `tracegraph-observability` that throws `BudgetExceededException` from `onUsage` once the per-execution sum exceeds threshold. Tests via `LlmCostListener` companion.
- [x] **Eval-harness module sketch** (DeepEval, Ragas, LangSmith evals) — new `tracegraph-eval` module: `GoldenTrace` loader from `JsonFileTraceStore`, `EvalRunner` re-executes a `Graph<S>` against each golden seed, `EvalReport` aggregating pass/fail + state diff. No external eval LLM dependency in v1.
- [x] **Supervisor multi-agent pattern** (CrewAI, AutoGen) — `SupervisorAgent<S>` factory in `tracegraph-connectors` producing a `Graph<S>` where a router LLM picks among N named `ReActAgent`s; uses `RoutingNode` + `subgraph` building blocks. Test with two trivial agents and a `MockLlmClient` routing harness.
- [x] **OTLP trace exporter** (Langfuse, Arize Phoenix) — `OtlpTraceExporter` in `tracegraph-observability` that consumes a `TraceStore` and emits per-step OTel spans (beyond `OtelNodeListener`'s live spans) for offline re-export. Weakness: persisted traces aren't replayable into APM tools.
- [x] **Docs gap audit** (LangGraph "Concepts" tree) — produce `docs/site/docs/competitive-gap-audit.md` listing missing concept pages (e.g., persistence, time-travel, breakpoints, double-texting, multi-agent), each linking to the existing TraceGraph primitive or marking `TODO: needs page`. No code change.
- [x] **Comparative micro-bench** — extend `tracegraph-bench` with a JMH benchmark contrasting `Graph.run` vs a hand-written sync executor on a linear 10-node graph. Document overhead in `tracegraph-bench/README.md`.

## Observability research batch (2026-05-17)

- [x] **Per-step token usage in traces** (LangSmith state snapshots) — ensure `TraceStep` carries `Usage(promptTokens, completionTokens)` populated from `NodeListener.onUsage`; verify `JsonFileTraceStore` and `JdbcTraceStore` persist it; add query helper `ExecutionTrace.totalUsage()`. Tests via `MockLlmClient` + `InMemoryTraceStore`. Weakness: token costs are tracked at listener level only, not queryable per execution step.
- [x] **Configurable sensitive-data logging flag** (Semantic Kernel diagnostic env vars) — add `Graph.Builder.sensitiveDataLogging(boolean)` (default `false`); when `true`, store full LLM prompt/response text in `TraceStep.rawInput` / `TraceStep.rawOutput`; when `false`, store only metadata (model name, token counts, finish reason). Propagate via `Context`. Tests with both flags. Weakness: no way to audit what data is stored in traces without code inspection.
- [ ] **Micrometer metrics bridge** (Spring AI `ChatClient` / LangChain4j Micrometer) — new `MicrometerNodeListener` in `tracegraph-observability` emitting `tracegraph.node.duration` timer, `tracegraph.node.errors` counter, `tracegraph.llm.tokens` counters to a `MeterRegistry`; wire via `Graph.Builder.listener(...)`. Tests with `SimpleMeterRegistry`. Weakness: no JVM throughput/latency metrics exported to Prometheus/Grafana-compatible systems.
- [ ] **Trace sampling wrapper** (Mastra sampling strategies) — `SamplingTraceStore(delegate, SampleStrategy)` in `tracegraph-observability` where `SampleStrategy` is a `@FunctionalInterface` receiving `ExecutionTrace<S>` and returning `boolean`; built-in strategies: `random(rate)`, `slowExecutions(thresholdMs)`, `failedOnly()`. Wire via `.traceRecorder(new RecordingTraceRecorder(new SamplingTraceStore(...)))`. Tests with deterministic strategies. Weakness: no way to control data volume for high-throughput graphs.
- [ ] **Multi-agent interaction correlation** (AutoGen message span tracking) — extend `ExecutionTrace` with optional `parentExecutionId` and `parentStepIndex` for subgraph / `sendAll` causality (mirrors `forkedFromExecutionId` pattern); populate in `RecordingTraceRecorder` when `Graph.runFrom` is called from a subgraph context. Update `JsonFileTraceStore` schema. Tests with a parent graph embedding a subgraph. Weakness: child execution traces are isolated; no link back to the parent step that spawned them.
- [ ] **Cost breakdown by node and provider** (Langfuse cost analytics) — extend `LlmCostListener` to expose `Map<String, Usage> usageByNode()` and `Usage totalUsage()` on a per-execution basis; add `LlmCostListener.snapshot(executionId)` returning an immutable `CostReport`. Tests with multi-node multi-LLM graph using `MockLlmClient`. Weakness: `LlmCostListener` accumulates global totals; no per-node or per-execution breakdown for billing.
- [ ] **OTel semantic conventions for LLM spans** (Semantic Kernel / OpenTelemetry GenAI SIG) — update `OtelNodeListener` to emit the [GenAI semantic convention](https://opentelemetry.io/docs/specs/semconv/gen-ai/) attributes (`gen_ai.system`, `gen_ai.request.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, `gen_ai.response.finish_reasons`) on spans for `ChatNode` executions. Tests via span attribute assertions. Weakness: current OTel spans use ad-hoc attribute names incompatible with standard APM dashboards.
- [ ] **Trace correlation ID for external system linkage** (LangGraph + Langfuse `trace_id`) — add `Graph.Builder.correlationId(Supplier<String>)` (or derive from incoming HTTP header); store in `ExecutionTrace.correlationId`; `OtlpTraceExporter` emits it as a span link attribute. `TraceController` returns it in `GET /tracegraph/traces/{id}`. Tests with a static supplier. Weakness: no way to correlate a TraceGraph execution with an upstream request trace in external APM.
- [ ] **Slow-node alert listener** (CrewAI task-level SLA) — `SlowNodeListener(Map<String, Duration> budgets, Consumer<SlowNodeEvent> handler)` in `tracegraph-observability`; fires `handler` when a node exceeds its named budget (or a default); does NOT throw, just notifies. Tests with a node that sleeps past its budget. Weakness: no built-in SLA enforcement or alerting when a node takes unexpectedly long.
- [ ] **Structured trace export to JSONL** (Haystack pipeline tracing export) — `JsonlTraceExporter.export(TraceStore, Path)` in `tracegraph-observability` writes one JSON object per `TraceStep` to a JSONL file suitable for ingestion by LangSmith, Langfuse, or Arize via their batch import APIs. Includes `executionId`, `nodeName`, `before`, `after`, `usage`, `durationMs`. Tests with `InMemoryTraceStore` seeded with known steps. Weakness: no bulk export format; traces can only be read through the REST API or `TraceStore.load(id)`.
