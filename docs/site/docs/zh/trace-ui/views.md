# 追踪 UI — 视图指南

Trace UI 提供四个视图，可通过顶部导航栏切换。本页介绍每个视图的功能及使用方法。

---

## 追踪列表（`#/traces`）

追踪列表是主页面，以表格形式展示每条已存储的执行记录，包含以下字段：

- **执行 ID** — 点击可打开详情视图。
- **状态** — `COMPLETED`（已完成）、`FAILED`（失败）、`INTERRUPTED`（已中断）或 `RUNNING`（运行中）。
- **开始时间** / **完成时间** — ISO 格式时间戳。
- **节点数量** — 已记录的步骤数。

**分页** — 使用上一页/下一页按钮，或设置每页条数来控制一次加载的行数。`X-Total-Count` 响应头用于驱动页数显示。

**筛选** — 在搜索框中输入部分执行 ID 或状态，可在客户端进行结果过滤。

---

## 追踪详情（`#/traces/:id`）

详情视图展示某条追踪记录的完整逐步执行历史。

### 步骤列表

每行是一个 `TraceStep`，包含：

- **节点名称** — 产生该步骤的节点。
- **重试次数** — 节点在成功（或失败）前的重试次数。
- **令牌用量** — LLM 节点的提示词和补全令牌数。
- **状态图标** — 成功显示绿色勾，失败显示红色叉。

点击某行可展开**状态差异面板**。

### 状态差异面板

以双列 JSON 差异形式显示所选步骤的前后状态。已更改字段会高亮显示。这是了解节点对状态所做修改的主要工具。

### 从该步骤回放

每行步骤都有一个**从此处回放**按钮。点击后发送：

```
POST /tracegraph/traces/{id}/replay?step=N
```

新的执行 ID 会以 Toast 通知形式显示，追踪列表随即刷新。派生追踪记录在其详情视图中会显示 `forkedFrom` 元数据。

### 恢复（中断的运行）

当追踪状态为 `INTERRUPTED` 时，详情视图顶部会出现**恢复**按钮。点击后发送：

```
POST /tracegraph/traces/{id}/resume
```

视图会轮询更新后的状态，直到运行完成或失败。

## 图结构（`#/graph`）

图结构视图将已编译的图渲染为可交互的有向无环图（DAG）。

- **节点**以矩形表示，标注节点名称。入口节点标有箭头进入图标；终止节点标有双边框。
- **边**以有向箭头表示。条件边显示谓词标签。
- **子图**以带标签的集群形式渲染（可折叠）。
- **并行组**以虚线框包含匿名分支。

将鼠标悬停在节点上可查看其重试策略（如已配置）。点击节点名称可跳转至上次执行中该节点最新的追踪步骤。

图数据来自 `GET /tracegraph/ui/graph`。

---

## 差异视图（`#/diff`）

差异视图并排比较两条执行追踪记录。

1. 从下拉菜单中选择**左侧追踪**和**右侧追踪**（或直接粘贴执行 ID）。
2. 点击**比较**。

视图调用 `GET /tracegraph/traces/{a}/diff/{b}` 并渲染：

- **匹配前缀** — 两条追踪中完全相同的步骤（节点名称 + 前后状态相同）。
- **分歧点** — 两条追踪首次出现差异的步骤索引，以橙色高亮显示。
- **左侧余量** — 分歧点之后仅存在于左侧追踪的步骤。
- **右侧余量** — 分歧点之后仅存在于右侧追踪的步骤。
- **摘要标签** — 状态相同？最终状态相同？完全一致？

使用差异视图可对比基线执行与回放结果，从而了解提示词修改或图结构变更带来的影响。
